# Plan d'implémentation : le Socle d'Eschaton

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un système Arch bootable qui s'identifie comme Eschaton, installable de façon reproductible en VM UTM aarch64 et en VM x86_64 émulée, avec snapshots bootables, dépôt de paquets hébergé et commandes de mise à jour/rollback.

**Architecture:** *Thin installer, fat packages* — un script `eschaton-install` minimal (partitionnement btrfs, pacstrap, Limine) et toute l'identité dans des meta-paquets pacman `arch=(any)` publiés sur un dépôt GitHub Pages. Le dev quotidien se fait dans une sandbox Docker Arch (build/lint/tests) et une VM UTM aarch64 (intégration).

**Tech Stack:** bash, PKGBUILD/makepkg/namcap, bats-core (tests shell), shellcheck, btrfs + snapper + snap-pac, Limine + limine-snapper-sync, zram-generator, Docker (sandbox Arch), UTM, GitHub Actions + GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-08-27-socle-design.md`

## Global Constraints

- Exécution dans un **worktree git dédié** (skill `superpowers:using-git-worktrees`), créé au démarrage.
- Tous les paquets `eschaton-*` sont `arch=(any)` ; le kernel est posé par l'installeur, jamais par un meta-paquet (spec §5.2).
- `eschaton-install` contient les deux branches d'architecture dès sa première version : aarch64 (`linux-aarch64`, pas de microcode, miroirs ALARM) et x86_64 (`linux`, `intel-ucode`/`amd-ucode` par détection, miroirs officiels) — spec §4.2.
- Layout disque exact (spec §4.3) : ESP 2 Gio FAT32 sur `/boot` ; btrfs avec subvolumes `@` → `/`, `@home` → `/home`, `@log` → `/var/log`, `@pkg` → `/var/cache/pacman/pkg`, `@snapshots` → `/.snapshots` ; swap **zram uniquement**.
- Dépôt `[eschaton]` : `SigLevel = Optional TrustAll` pour ce dépôt **uniquement** (dette v0, spec §5.3) ; les dépôts Arch gardent leur vérification.
- **Aucun système de migrations** (spec §3). Les valeurs par défaut vivent dans `/usr/`, les personnalisations dans `/etc/`. Trois écritures de provisioning sont autorisées à l'installation uniquement : `/etc/os-release` (copie), une ligne `Include` dans `/etc/pacman.conf`, `SNAPPER_CONFIGS` dans `/etc/conf.d/snapper`.
- Défauts d'installation : locale `fr_FR.UTF-8`, clavier `fr`, fuseau `Europe/Paris`, hostname `eschaton` (spec §4.2).
- Boot **UEFI uniquement**, disque entier (pas de dual-boot) — spec §4.2.
- Tests : shellcheck sur tout script bash, namcap sur tout paquet, bats-core pour les fonctions pures. Commits fréquents (un par étape verte).
- Les scripts bash ont le shebang `#!/usr/bin/env bash` (macOS a bash 3.2 en `/bin/bash` ; on utilise le bash 5 de brew côté Mac).

- [ ] **Step 5 : Écrire les wrappers**

`eschaton-update` :

```bash
#!/usr/bin/env bash
set -euo pipefail
source /usr/lib/eschaton/lib.sh
min_kb=1048576  # 1 Gio de marge avant update
avail_kb=$(df --output=avail -k / | tail -1 | tr -d ' ')
if ! check_free_space_kb "$avail_kb" "$min_kb"; then
  echo "eschaton-update : moins de 1 Gio libre sur /, libère de l'espace d'abord." >&2
  exit 1
fi
echo "==> Mise à jour (Arch + [eschaton]). Snapshot automatique via snap-pac."
sudo pacman -Syu "$@"
if running_kernel_missing_modules /usr/lib/modules "$(uname -r)"; then
  echo "==> Le kernel a été mis à jour : redémarre pour l'utiliser (sudo reboot)."
fi
```

`eschaton-rollback` :

```bash
#!/usr/bin/env bash
set -euo pipefail
echo "==> Points de restauration disponibles :"
sudo snapper --config root list
read -rp "Numéro du snapshot vers lequel revenir (vide pour annuler) : " num
[[ -z "$num" ]] && { echo "Annulé."; exit 0; }
[[ "$num" =~ ^[0-9]+$ ]] || { echo "Numéro invalide." >&2; exit 1; }
sudo snapper --config root rollback "$num"
echo "==> Rollback préparé. Redémarre pour démarrer sur l'état restauré (sudo reboot)."
```

```bash
#!/usr/bin/env bash
# Fonctions d'eschaton-install. DRY_RUN=1 => run_cmd imprime au lieu d'exécuter.

run_cmd() {
  if [[ "${DRY_RUN:-0}" == "1" ]]; then echo "DRY: $*"; else "$@"; fi
}

detect_arch() { uname -m; }

kernel_pkgs_for() { # $1 = aarch64|x86_64
  case "$1" in
    aarch64) echo "linux-aarch64" ;;
    x86_64)  echo "linux intel-ucode amd-ucode" ;;
    *) echo "architecture non gérée : $1" >&2; return 1 ;;
  esac
}

microcode_for_cpu() { # x86_64 uniquement : détection du vendeur
  if grep -q GenuineIntel /proc/cpuinfo 2>/dev/null; then echo intel-ucode
  elif grep -q AuthenticAMD /proc/cpuinfo 2>/dev/null; then echo amd-ucode
  fi
}
```

- [ ] **Step 4 : Écrire `installer/eschaton-install`**

```bash
#!/usr/bin/env bash
# Installeur Eschaton — spec docs/superpowers/specs/2026-08-27-socle-design.md §4.
# S'exécute depuis un environnement live Arch (archboot aarch64 / ISO officielle x86_64).
set -euo pipefail
source "$(dirname "$0")/lib.sh"

DRY_RUN=0; DISK=""; HOSTNAME_="eschaton"; USERNAME=""
while [[ $# -gt 0 ]]; do
  case "$1" in
    --dry-run) DRY_RUN=1 ;;
    --disk) DISK="$2"; shift ;;
    --hostname) HOSTNAME_="$2"; shift ;;
    --user) USERNAME="$2"; shift ;;
    *) echo "option inconnue : $1" >&2; exit 1 ;;
  esac; shift
done
export DRY_RUN
[[ -n "$DISK" && -n "$USERNAME" ]] || { echo "usage: eschaton-install [--dry-run] --disk /dev/X --user NOM [--hostname H]" >&2; exit 1; }

# Précondition spec §4.2 : boot UEFI uniquement
if [[ "$DRY_RUN" == "0" && ! -d /sys/firmware/efi ]]; then
  echo "eschaton-install : boot UEFI requis (dossier /sys/firmware/efi absent)." >&2; exit 1
fi

arch="$(detect_arch)"
kernels="$(kernel_pkgs_for "$arch")"
if [[ "$arch" == "x86_64" && "$DRY_RUN" == "0" ]]; then
  kernels="linux $(microcode_for_cpu)"
fi

# 1. Partitionnement (spec §4.3) — ESP 2 Gio + btrfs sur le reste
run_cmd sgdisk --zap-all "$DISK"
run_cmd sgdisk -n1:0:+2G -t1:ef00 -c1:ESP "$DISK"
run_cmd sgdisk -n2:0:0 -t2:8300 -c2:eschaton "$DISK"
part() { [[ "$DISK" == *[0-9] ]] && echo "${DISK}p$1" || echo "${DISK}$1"; }
run_cmd mkfs.vfat -F32 -n ESP "$(part 1)"
run_cmd mkfs.btrfs -f -L eschaton "$(part 2)"

# 2. Subvolumes
run_cmd mount "$(part 2)" /mnt
for sv in @ @home @log @pkg @snapshots; do run_cmd btrfs subvolume create "/mnt/$sv"; done
run_cmd umount /mnt
opts="compress=zstd:1,noatime"
run_cmd mount -o "subvol=@,$opts" "$(part 2)" /mnt
run_cmd mkdir -p /mnt/home /mnt/var/log /mnt/var/cache/pacman/pkg /mnt/.snapshots /mnt/boot
run_cmd mount -o "subvol=@home,$opts" "$(part 2)" /mnt/home
run_cmd mount -o "subvol=@log,$opts" "$(part 2)" /mnt/var/log
run_cmd mount -o "subvol=@pkg,$opts" "$(part 2)" /mnt/var/cache/pacman/pkg
run_cmd mount -o "subvol=@snapshots,$opts" "$(part 2)" /mnt/.snapshots
run_cmd mount "$(part 1)" /mnt/boot

# 3. Dépôt [eschaton] dans le live env, puis pacstrap
run_cmd bash -c 'grep -q "^\[eschaton\]" /etc/pacman.conf || printf "\n[eschaton]\nSigLevel = Optional TrustAll\nInclude = /etc/pacman.d/eschaton-mirror\n" >> /etc/pacman.conf'
run_cmd bash -c 'echo "Server = https://REMPLACER-EN-TASK-8.github.io/eschaton" > /etc/pacman.d/eschaton-mirror'
# shellcheck disable=SC2086
run_cmd pacstrap -K /mnt base $kernels eschaton-base eschaton-branding
run_cmd bash -c 'genfstab -U /mnt >> /mnt/etc/fstab'

# 4. Configuration dans le chroot (spec §4.2 étape 5 + provisioning autorisé)
chroot_cmd() { run_cmd arch-chroot /mnt bash -c "$1"; }
chroot_cmd 'ln -sf /usr/share/zoneinfo/Europe/Paris /etc/localtime && hwclock --systohc || true'
chroot_cmd 'sed -i "s/^#fr_FR.UTF-8/fr_FR.UTF-8/; s/^#en_US.UTF-8/en_US.UTF-8/" /etc/locale.gen && locale-gen'
chroot_cmd 'echo LANG=fr_FR.UTF-8 > /etc/locale.conf && echo KEYMAP=fr > /etc/vconsole.conf'
run_cmd bash -c "echo '$HOSTNAME_' > /mnt/etc/hostname"
chroot_cmd 'cp /usr/share/eschaton/os-release /etc/os-release'
# Provisioning autorisé (spec §3) : activer le dépôt [eschaton] sur le système cible
chroot_cmd 'grep -q "eschaton.conf" /etc/pacman.conf || printf "\nInclude = /etc/pacman.d/eschaton.conf\n" >> /etc/pacman.conf'
chroot_cmd 'sed -i "s/^SNAPPER_CONFIGS=.*/SNAPPER_CONFIGS=\"root\"/" /etc/conf.d/snapper'
chroot_cmd "useradd -m -G wheel $USERNAME"
if [[ "$DRY_RUN" == "0" ]]; then arch-chroot /mnt passwd "$USERNAME"; else echo "DRY: passwd $USERNAME"; fi
chroot_cmd 'systemctl preset-all'

# 5. Limine (UEFI, chemin de boot par défaut)
if [[ "$arch" == "aarch64" ]]; then efi=BOOTAA64.EFI; else efi=BOOTX64.EFI; fi
chroot_cmd "mkdir -p /boot/EFI/BOOT && cp /usr/share/limine/$efi /boot/EFI/BOOT/$efi"
kernel_name="${kernels%% *}"
run_cmd bash -c "cat > /mnt/boot/limine.conf <<EOF
timeout: 3

/Eschaton
    protocol: linux
    path: boot():/vmlinuz-$kernel_name
    module_path: boot():/initramfs-$kernel_name.img
    cmdline: root=LABEL=eschaton rootflags=subvol=@ rw quiet
EOF"

echo "==> Installation terminée. Redémarre (umount -R /mnt && reboot)."
```

# Construit tous les paquets du monorepo et produit le dépôt pacman dans repo/out/.
set -euo pipefail
root="$(cd "$(dirname "$0")/.." && pwd)"
out="$root/repo/out"; mkdir -p "$out"

id builder &>/dev/null || useradd -m builder
shopt -s nullglob

namcap "$out"/*.pkg.tar.* || true   # lint informatif (spec §7.4) — faux positifs fréquents sur les meta-paquets
(cd "$out" && repo-add --new eschaton.db.tar.gz ./*.pkg.tar.*)
ls -l "$out"
