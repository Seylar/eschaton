# Plan d'implémentation : l'ISO (SP4b-1)

> **Exécution : Codex.** Gates : Claude. **Branche dédiée `iso`** (à créer depuis `main`) — ce chantier est indépendant de l'update graphique, les deux peuvent avancer en parallèle sans se marcher dessus.
> **Spec (autorité)** : [`2026-08-29-iso-design.md`](../specs/2026-08-29-iso-design.md). **Périmètre matériel** : [ADR 0004](../../decisions/0004-perimetre-materiel-mac-t2.md) — le T2 est *toléré et cloisonné*, jamais supporté.

**Goal :** un média Eschaton amorçable qui installe le système — d'abord en VM x86_64 (le produit), puis sur le MacBook Pro 2019 de l'auteur (le banc).

---

### Task 1 : Profil `archiso` nominal, construit localement

1. Partir du profil `releng`, le réduire à notre besoin ; `packages.x86_64` versionné.
2. Embarquer : `eschaton-install` et ses dépendances, le dépôt `[eschaton]` préconfiguré, **`iwd` et non `wpa_supplicant`** (régression 2.11 constatée par la veille T2), outils de secours (`snapper`, `btrfs-progs`, `limine`).
3. Réserver la place du keyring (SP4a) sans l'attendre : le dépôt reste `Optional` pour l'instant, mais le profil ne devra pas être retouché ensuite.
4. Construction locale reproductible, **taille mesurée** (cible ≤ 2 Gio).

### Task 2 : Démarrage et installation prouvés en VM x86_64

1. L'ISO démarre en UEFI dans une VM ; l'environnement live est utilisable.
2. **Installation complète** avec `eschaton-install`, jusqu'au premier démarrage en session graphique avec les pastilles rendues.
3. Solder au passage les différés d'installeur routés SP4 par le bilan du Socle : `partprobe`/`udevadm settle`, validation des arguments (`--disk` dernier token, `[[ -b ]]`, interpolation `user`/`hostname`), `visudo -cf` en CI.
4. Durées réelles consignées.

### Task 3 : Construction en CI et publication

1. Job de construction x86_64 en CI, liste de paquets versionnée, immutabilité respectée.
2. Publication en **GitHub Release** (l'ISO ne tient pas sur Pages : 1 Gio par site, contre 2 Gio par fichier en Release).
3. Somme de contrôle publiée à côté de l'image.
4. **Épingler les actions CI par SHA** — c'est désormais un prérequis de sécurité, pas une hygiène (la clé de signature approchera la CI au SP4a).

### Task 4 : Variant T2 — construction ⚠️ (dépend de points utilisateur)

> **Ne démarre cette tâche que si les points ouverts de l'[ADR 0004 §6](../../decisions/0004-perimetre-materiel-mac-t2.md) sont tranchés** (taille d'écran, sort de macOS, ratification). Les Tasks 1-3 n'en dépendent pas.

1. Variant du profil : `linux-t2`, `apple-bce`, `apple-bcm-firmware`. **La divergence reste une liste de paquets**, jamais une fourche du profil.
2. Dépôt tiers `arch-mact2` utilisé **uniquement** pour la construction du variant — il n'entre jamais dans la configuration par défaut d'un système Eschaton.
3. **Ne pas publier ce variant** : zone grise du firmware Apple redistribué (spec §3.3). Artefact interne.
4. Garde d'épinglage du noyau : le paquet `linux` standard ne doit jamais s'installer sur une machine T2.

### Task 5 : La vraie machine ⚠️ (l'utilisateur seul peut la conduire)

Cette tâche exige la machine physique de l'auteur ; elle sera menée **avec lui**, pas à sa place. Préparer un mode opératoire pas à pas, puis consigner :

1. Démarrage sécurisé désactivé via le Startup Security Utility (« No Security » + démarrage externe).
2. L'ISO démarre, **voit le disque**, installe ; premier démarrage réussi.
3. Clavier et trackpad internes fonctionnels ; **Wi-Fi opérationnel sans passer par macOS**.
4. **Preuve de rollback sur la vraie machine** : cassage volontaire, restauration depuis le shell, redémarrage vérifié. C'est le test de résistance le plus sévère de notre fonctionnalité phare (ADR 0004 §4.4).

### Task 6 : Clôture

DoD spec §4 point par point, réserves écrites (Secure Boot non supporté, défauts T2 connus, zone grise du firmware), statut de la spec, **notifier pour la revue Claude**.
